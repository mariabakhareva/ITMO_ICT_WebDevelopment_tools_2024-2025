    Services

    Слой services в архитектуре приложения служит для инкапсуляции бизнес-логики. Он отделяет низкоуровневую работу с базой данных (через ORM/SQLModel) от маршрутов (routes) и контроллеров. Такой подход упрощает поддержку, тестирование и масштабирование приложения.

    Основные цели:

    • Снижение связности кода и соблюдение принципов SOLID
    • Централизация логики CRUD-операций
    • Повышение читаемости и повторного использования
    • Упрощение внедрения валидаций, кэширования и логирования

    Обзор функциональности по модулям

    journey_stop

    Функции для управления остановками путешествия (JourneyStop)

    • get_journey_stops(session, journey_id). Получение списка остановок для конкретного путешествия
    • add_journey_stop(session, stop). Добавление новой остановки с автоматическим выставлением времени создания
    • delete_journey_stop(session, journey_id, stop_id). Удаление остановки по ID с проверкой принадлежности к нужному путешествию

    journey

    Функции для управления сущностью Journey и связанными объектами

    • get_journeys(session). Получение всех путешествий
    • get_journey(session, journey_id). Получение одного путешествия по ID с предзагрузкой всех связанных сущностей: автор (creator), участники (participants + user), сообщения , остановки
    • get_journeys_by_user(session, user_id). Получение путешествий, созданных конкретным пользователем
    • create_journey(session, journey). Создание нового путешествия
    • update_journey(session, journey_id, journey). Обновление полей существующего путешествия (только заданные поля)
    • delete_journey(session, journey_id). Удаление путешествия

    message

    Функции для работы с сообщениями (Message)

    • get_messages(session, journey_id). Получение всех сообщений, связанных с конкретным путешествием
    • create_message(session, message). Добавление нового сообщения

    participant

    Функции для управления участниками путешествия (Participant)

    • get_participants(session, journey_id). Получение всех участников конкретного путешествия
    • create_participant(session, participant). Добавление участника
    • update_participant(session, participant_id, participant). Обновление информации об участии (например, статус)
    • delete_participant(session, participant_id). Удаление участника

    user

    Функции для управления пользователями (User) и аутентификацией

    • get_all_users(session). Получение всех пользователей без паролей
    • get_user_by_id(session, user_id). Получение пользователя по ID
    • create_user(session, user). Создание пользователя с хэшированием пароля
    • update_user(session, user_id, user). Обновление профиля пользователя
    • delete_user(session, user_id). Удаление пользователя
    • login_user(session, username, password). Аутентификация: проверка пароля и генерация access token
    • register_user(session, user). Регистрация пользователя с проверкой на уникальность и хэшированием пароля
    • change_password(session, user_id, old_password, new_password). Смена пароля после проверки текущего
