    Работа с базой данных и миграциями Alembic

    В проекте используется SQLModel для работы с базой данных и Alembic для управления миграциями.

    Подключение к базе данных

    Конфигурация подключения к базе данных осуществляется через переменные окружения, которые считываются с помощью dotenv. Строка подключения хранится в .env файле и передаётся в движок SQLAlchemy через DATABASE_DSN.

    Работа с SQLModel

    Файл db/connection.py содержит основные функции для работы с БД:

    • engine создаётся с помощью create_engine и использует строку подключения из конфигурации.
    • init_db() — инициализирует структуру базы, создавая все таблицы, описанные в моделях.
    • get_session() — зависимость FastAPI, возвращающая сессию для взаимодействия с БД внутри запроса.

    Модели, определённые с использованием SQLModel, автоматически добавляются в metadata, которая используется для создания таблиц и миграций.

    Миграции с Alembic

    Alembic используется для версионирования схемы базы данных. Основные настройки находятся в файле alembic/env.py, где подключается engine из проекта и передаётся SQLModel.metadata как целевая метадата (target_metadata). Это позволяет Alembic отслеживать изменения в моделях и автоматически генерировать миграции.

    В alembic.ini задаётся строка подключения к базе данных. Alembic использует эту строку при выполнении миграций.

    Создание и применение миграций

    Для создания новой миграции используется команда:

    • alembic revision --autogenerate -m "описание" — генерирует миграционный скрипт на основе изменений в моделях.

    Для применения миграции:

    • alembic upgrade head — применяет все доступные миграции к базе данных.

    Для отката:

    • alembic downgrade -1 — отменяет последнюю миграцию.

    Разница между init_db и Alembic

    Метод init_db() использует create_all() для создания таблиц и подходит в основном для начальной разработки или тестов. Однако он не отслеживает изменения схемы — для этого и нужен Alembic. Alembic позволяет безопасно вносить изменения в структуру базы без потери данных, сохраняя историю изменений и поддерживая согласованность схемы между окружениями.

    Вывод

    Использование SQLModel в сочетании с Alembic обеспечивает удобную и надёжную работу с базой данных. SQLModel предоставляет декларативный синтаксис для описания моделей, а Alembic — мощный механизм миграций, позволяющий управлять схемой базы данных в любой стадии жизненного цикла проекта.
