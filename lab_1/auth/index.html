    Авторизация и Ролевая Модель в проекте

    В проекте реализована авторизация с использованием JWT-токенов (JSON Web Token). Система поддерживает несколько ролей пользователей, включая user и admin, с соответствующими уровнями доступа.

    Механизм авторизации

    1. Создание и верификация паролей

    Для безопасности пароли пользователей хранятся в зашифрованном виде с использованием библиотеки passlib, которая предоставляет хеширование с алгоритмом bcrypt.

    • verify_password(plain_password: str, hashed_password: str) -> bool: Функция для проверки правильности пароля. Она использует хеширование для сравнения введённого пароля с сохранённым в базе данных.

    • get_password_hash(password: str) -> str: Функция для создания хеша пароля, который сохраняется в базе данных.

    В проекте для хэширования паролей используется библиотека passlib, которая поддерживает различные алгоритмы хэширования. В данном случае используется алгоритм bcrypt, который считается безопасным и устойчивым к атакам.

    Процесс хэширования

    • Когда пользователь вводит свой пароль, он проходит через функцию get_password_hash, которая создаёт хешированную версию пароля. Этот хеш сохраняется в базе данных, и при следующем входе он будет использован для проверки правильности введённого пароля. pwd_context.hash(secret=password): использует контекст CryptContext, чтобы хэшировать переданный пароль с использованием алгоритма bcrypt.
    • Когда пользователь пытается войти в систему, введённый им пароль сравнивается с сохранённым хешем. Для этого используется функция verify_password, которая выполняет проверку: pwd_context.verify(secret=plain_password, hash=hashed_password): проверяет, совпадает ли введённый пароль с хешем, сохранённым в базе данных. Алгоритм bcrypt выбран, потому что он предназначен для защиты паролей и предлагает достаточную защиту от атак типа brute-force. Он также поддерживает настройку "соли" (random salt), что делает хэширование паролей ещё более безопасным.

    2. JWT-авторизация

    Для авторизации используется механизм JWT, который позволяет безопасно передавать информацию о пользователе через токен.

    • create_access_token(role: str, user_id: int, expires_delta: timedelta | None = None) -> str: Функция для создания JWT-токена, который включает в себя роль пользователя (scope), его ID (user_id) и срок действия токена (exp). Срок действия токена можно указать при создании, либо по умолчанию устанавливается на 7 дней.

    • decode_access_token(token: str) -> dict: Функция для декодирования JWT-токена и извлечения данных. Если токен истёк или является недействительным, возвращается ошибка.

    3. Доступ по ролям

    Ролевая модель предполагает несколько уровней доступа:

    • admin: Имеет полный доступ ко всем ресурсам в системе.
    • user: Имеет доступ только к своим данным и может выполнять действия в рамках своего путешествия.

    3.1 Проверка прав доступа

    В проекте реализованы несколько функций, которые проверяют, имеет ли пользователь права для выполнения определённого действия:

    • get_current_admin: Функция, которая проверяет, является ли пользователь администратором. Если у пользователя нет соответствующих прав, выбрасывается ошибка с кодом 403 (Forbidden).

    • get_user_permission: Функция для проверки прав пользователя на доступ к его данным. Проверяется, совпадает ли ID текущего пользователя с ID в токене или является ли пользователь администратором.

    • get_user_permission_by_journey: Проверка прав доступа пользователя к путешествию. Пользователь должен быть участником указанного путешествия для выполнения определённых действий.

    • get_initiator_permission: Проверка прав доступа к путешествию для его создателя. Только создатель путешествия (инициатор) имеет право редактировать или удалять его.

    • get_message_permission: Проверка прав пользователя на доступ к сообщениям в путешествии. Пользователь должен быть участником путешествия, чтобы получить доступ к сообщениям.

    "Интересные" моменты

    1. JWT-секрет (JWT_SECRET) используется для подписания и верификации токенов. Он должен храниться в безопасном месте и быть доступен только серверу.

    2. Права доступа: Все проверки прав доступа основаны на данных, закодированных в JWT-токенах, что упрощает авторизацию и делает систему масштабируемой.

    3. Роли пользователей: Каждый пользователь получает роль, которая определяет его уровень доступа. Администратор может выполнять любые операции, в то время как пользователь ограничен доступом только к собственным данным.
