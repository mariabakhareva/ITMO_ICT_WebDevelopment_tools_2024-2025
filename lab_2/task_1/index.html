    Task_1

    Сравнение: Threading vs Multiprocessing vs Async в Python

    Задача: Сумма чисел от 1 до 10_000_000_000_000, разбитая на параллельные вычисления.

    Пояснение по коду

    Threading

    import threading
import time

def calculate_sum(start: int, end: int) -> int:
    return (end - start + 1) * (start + end) // 2

def thread_task(start: int, end: int, storage: list, idx: int):
    storage[idx] = calculate_sum(start, end)

if __name__ == "__main__":
    upper_limit = 10_000_000_000_000
    thread_count = 10
    segment = upper_limit // thread_count

    results = [0] * thread_count
    thread_pool = []

    start_time = time.perf_counter()
    for i in range(thread_count):
        begin = i * segment + 1
        finish = (i + 1) * segment if i < thread_count - 1 else upper_limit
        t = threading.Thread(target=thread_task, args=(begin, finish, results, i))
        t.start()
        thread_pool.append(t)

    for t in thread_pool:
        t.join()

    total = sum(results)
    end_time = time.perf_counter()

    print(f"Threading: result = {total}, duration = {end_time - start_time:.6f} seconds")
    • Используем 10 потоков.
    • Каждый считает сумму своей части.
    • Потоки работают в одной памяти.
    • Почти нет накладных расходов (легко создать и управлять).
    • GIL (ограничение Python) не мешает, потому что: потоки не конфликтуют, все делают независимую арифметику.

    Multiprocessing

    import multiprocessing as mp
import time

def calculate_sum(start: int, end: int) -> int:
    return (end - start + 1) * (start + end) // 2

def perform_task(params):
    return calculate_sum(*params)

if __name__ == "__main__":
    upper_limit = 10_000_000_000_000
    workers = mp.cpu_count()
    portion = upper_limit // workers

    ranges = []
    for idx in range(workers):
        from_val = idx * portion + 1
        to_val = (idx + 1) * portion if idx != workers - 1 else upper_limit
        ranges.append((from_val, to_val))

    start_time = time.perf_counter()
    with mp.Pool(processes=workers) as executor:
        output = executor.map(perform_task, ranges)
    final_sum = sum(output)
    end_time = time.perf_counter()

    print(f"Multiprocessing: result = {final_sum}, duration = {end_time - start_time:.6f} seconds")
    • Используем столько процессов, сколько ядер у CPU.
    • Каждый процесс получает свой диапазон.
    • Но процессы не делят память — данные передаются через каналы (IPC).
    • Создание и управление процессами дороже, чем потоками.

    Asyncio

    import asyncio
import time

async def calculate_sum(start: int, end: int) -> int:
    return (end - start + 1) * (start + end) // 2

async def compute_aggregate():
    max_value = 10_000_000_000_000
    segments = 4
    segment_size = max_value // segments

    tasks = []
    for segment in range(segments):
        begin = segment * segment_size + 1
        finish = (segment + 1) * segment_size if segment < segments - 1 else max_value
        tasks.append(asyncio.create_task(calculate_sum(begin, finish)))

    results = await asyncio.gather(*tasks)
    return sum(results)

if __name__ == "__main__":
    start_clock = time.perf_counter()
    overall_sum = asyncio.run(compute_aggregate())
    end_clock = time.perf_counter()

    print(f"Async: result = {overall_sum}, duration: {end_clock - start_clock:.6f} seconds")
    • Используем async/await и asyncio.create_task.
    • Работает в одном потоке.
    • Подходит для задач с ожиданием (например, загрузка с интернета).
    • Здесь нет ожидания — просто математика, так что выигрыша почти нет.

    Результаты

    Метод Результат Время (сек)
    Threading 5e+25 0.000535
    Asyncio 5e+25 0.000665
    Multiprocessing 5e+25 0.204758

    Выводы

    • Threading — самый быстрый: простая формула + низкий overhead + нет блокировок.
    • Async не даёт выигрыша — нет I/O.
    • Multiprocessing — проигрывает из-за затрат на процессы и IPC.
